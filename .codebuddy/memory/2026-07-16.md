## 紧急修复：后端响应被多包一层 list（导致前端白屏 .find 崩）
- **现象**：安装版里 `Optimize` 页面（及潜在所有页面）报 `Cannot read properties of undefined (reading 'find')`。`Pe`(Optimize.tsx:42 `strategies.find`) 在渲染期崩。
- **根因**：`backend/main.py` 的 `_safe_json_dumps` 里一行 `(tuple(_clean_nan(a) for a in args[:1]) + args[1:],)` **外层多了圆括号**，把单元素元组又包了一层 tuple，导致 `json.dumps(*((obj,),))` 实际变成 `json.dumps((obj,))` 序列化成 **JSON 数组 `[obj]`**。即每个接口响应都被多包一层 `[]`，前端 `res.data` 拿到 `[{status,data}]`，`res.data.data` 为 `undefined`。Optimize.tsx 没 `|| []` 兜底所以白屏；其他页面（StockScan 等有 `|| []`）侥幸不崩。
- **修复**：
  1. `backend/main.py`：改为 `cleaned_first = _clean_nan(args[0]); args = (cleaned_first,) + args[1:]`，不再双重 tuple 包裹。验证 render 输出以 `{` 开头、HTTP `/api/strategy/list` 返回 `{"status":"ok","data":[...]}` 正确。
  2. `frontend/src/pages/Optimize.tsx`：`const list = res.data.data || []` 防御性兜底。
- **影响范围**：该 bug 是全局性的（所有 API 响应），非本轮 P2 修改引入（main.py 的 NaN 清洗逻辑一直如此）。用户是在本轮打包后才首次暴露——可能因之前未走到该代码路径或测试不充分。
- **需重新打包**使修复进安装版。
